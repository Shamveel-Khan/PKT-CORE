## 9. Storage telemetry — `/mnt/oldpc` (LUKS2 `sdb3`)

Recorded during Phase 1 because it directly bounds corpus coverage.

| Fact | Observation |
| --- | --- |
| Backing device | `sdb3` → `oldpc_crypt` (dm-2) → `oldpc--vg-ubuntu--lv` (dm-3), mounted **read-only** at `/mnt/oldpc` |
| LUKS | LUKS2, `aes-xts-plain64`, 512-bit key, argon2id keyslot 0. Header clean. Provided passphrase **verified valid** (`cryptsetup open --test-passphrase`). |
| Unlock state | Already unlocked; key resident in kernel keyring. **Encryption is not the blocker.** |
| SMART | `PASSED` — drive self-assessment healthy |
| Filesystem | ext4 damage: `__ext4_get_inode_loc_noinmem: unable to read itable block`, `Can't read a block bitmap` (debugfs will not open the FS) |
| Media | Scattered unreadable sectors across the whole volume — alternating `+`/`-` regions in `ddrescue` mapfiles, ~4 bad areas per 64 MiB near the head |
| LVM | `lvs`/`pvs` do **not** enumerate `oldpc-vg`; the LV is a stale manual mapping |

**Effect on corpus:** 31 of 69 discovered files are unreadable. Of those, **9 are exact
SHA-256 duplicates** of files secured elsewhere, so the true loss is ~22 files:
`Documents/PT9-RE-*.pkt` (reproducible from the in-tree generator), `uwu.pkt`,
`JSDF-AWACS*`, and `pt/saves/{AWACSJSDFPR7,AWACSJSDFPR7-BACKUP,ptalb}.pka`.

**Recovery status:** deferred to the `RECOVERY` workstream (see `ANALYSIS_PLAN.md` §7).
The modern container is fully deterministic (fixed key + fixed IV ⇒ file-independent
keystream), which makes signature-free carving of the readable sectors feasible.
